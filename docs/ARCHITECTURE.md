# Архитектура

## Принципы

1. **Расчёт отделён от UI.** Пакет `src/cosmo` не знает о Streamlit;
   `app.py` только читает виджеты, вызывает функции ядра и рисует.
2. **Официальная модель — единственный источник геометрии.** Все
   координаты, активность, рёбра и углы возвышения берутся из
   `vendor/geometry.py` (копия организаторов без изменений) через
   `geometry_adapter`. Собственный движок (`positions_own`, `snapshot_own`)
   существует для parity-тестов и написан строго по формулам
   «Описание данных».
3. **Детерминизм.** Те же входные данные → тот же результат: сортировка
   соседей по ID, лексикографический tie-break, фиксированный seed
   оптимизатора.
4. **Никаких хардкодов данных.** ID (C65, G_MUR, S01…), число спутников,
   плоскостей, тиков — всё выводится из сценария. Скрытый сценарий жюри
   с другими ID/значениями пройдёт без правок кода.

## Поток данных

```
JSON-файл / built-in
   │  validate_scenario (наши сообщения) + geometry.validate (safety net)
   ▼
base_scenario (session_state) ── виджеты (launch_stage, RAAN/phase,
   │                             failures, advanced) ──► effective_scenario
   ▼
cached_simulate(scenario_json, strategy)         ← st.cache_data, ключ = хэш JSON
   │  simulate_scenario:
   │    для t в range(0, horizon, step):
   │        geometry.snapshot(scenario, t) → build_link_graph
   │        find_route(клиент) → статус/причина/путь (+ резервный путь)
   ▼
SimulationResult (иммутабельные dataclasses, кортежи)
   │
   ├── metrics.py → ClientMetrics / GlobalMetrics
   ├── visualization.py → Plotly-фигуры
   ├── comparison.py / resilience.py / optimizer.py
   └── export.py → result JSON / CSV
```

## Состояние интерфейса

- `base_scenario` — сценарий как загружен (источник сброса).
- Виджеты ключуются с `nonce`, который растёт при каждой загрузке
  сценария, — это сбрасывает их значения к данным нового файла.
- Таблицы отказов (`st.data_editor`) нельзя инициализировать через
  `session_state[key]`, поэтому они хранятся в seed-списках и
  передаются параметром `data`; правки читаются из состояния виджета
  (`DataEditorState` применяется к seed функцией `rows_from_editor`).
- Навигация разделов — `st.radio` (сохраняется при перерасчётах, в
  отличие от `st.tabs`).

## Кэширование

- `cached_simulate(scenario_json, strategy)` — ключ: канонический JSON
  эффективного сценария + стратегия. Полный расчёт 720 тиков ≈ 0.3–0.6 с.
- `cached_criticality` — анализ критичности по хэшу сценария.
- Snapshot выбранного момента для 3D-сети пересчитывается дёшево на лету
  (один вызов geometry.snapshot ≈ 1 мс).

## Расширяемость

- Новая стратегия маршрутизации: добавить функцию в `routing.py`
  и ветку в `find_route`; UI и экспорт подхватят автоматически.
- Дополнительная аналитика (пропускная способность, задержки) — отдельным
  модулем поверх `SimulationResult`; в обязательную модель не включалась
  (по документу «Описание данных» показатели геометрические).
