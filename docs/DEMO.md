# Демонстрация — 4 минуты (регламент: 4 мин выступление + 2 мин вопросов)

Сюжет один: **есть проект → считаем доступность → реальный маршрут → ломаем
спутник → перестроение или диагностированный разрыв → сравниваем две
конфигурации → рекомендация**. Docker, тесты и архитектуру на живом демо не
показываем — они на слайдах и в README.

Подготовка: открыть приложение (`streamlit run app.py` или публичный URL),
сценарий 01 загружается и считается автоматически. Заранее ничего не настраивать.

| 2 | 0:30–1:15 | «Сеть и время»: t≈12:00, клиент C65 | «Маршрут минимальной геометрической длины строится на каждом отсчёте: цепочка до шлюза, переходы включают две наземные линии. Двигаем время — маршрут перестраивается сам» |

Финальная фраза: «Рекомендация команды — все три очереди и МСC 3000 км:
только эта конфигурация закрывает 90% для всех пунктов».

### Подготовка до защиты (2 минуты)

1. Открыть сервис, рассчитать базовый сценарий 01.
2. Изменить RAAN плоскости P1 на 30° → «Пересчитать» → «💾 Сохранить вариант»
   (это будет «Вариант 1» для шага 6).
3. Вернуть P1 = 0°, «Пересчитать» — базовое состояние на экране.

### Если спросят (запасные вкладки, на время не тратить)

- «А если шлюз встанет?» — Advanced-панель, `gateway_outages` (движок поддерживает).
- «Как подбирали фазирование?» — «Устойчивость» → быстрый подбор RAAN/фазы
  ( coarse-поиск + подтверждение на полной сетке).
- «А рельеф/застройка?» — честно: не в базовой модели по документу; следующий
  этап — site-specific horizon mask поверх официальной модели возвышения.

Ответы на технические вопросы — docs/TECHNICAL_QA.md.
