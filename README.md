# Устойчивая спутниковая группировка — веб-сервис проектирования

Веб-сервис для инженера-проектировщика: загрузка сценария группировки
(формат `cosmo-A-1.0`), изменение конфигурации, моделирование сети на
суточной сетке, маршрутизация «клиент → спутники → шлюз», диагностика
перерывов, сравнение вариантов, анализ устойчивости и экспорт результата
в официальном формате `cosmo-A-result-1.0`.

Кейс КосмоХакатона 2026 «Проектирование устойчивой спутниковой группировки».

## Что решает

- **Проектирование**: выбор этапа развёртывания (1/2/3), изменение RAAN и
  фазирования каждой плоскости, редактирование периодов отказов спутников
  и шлюзов в экранных формах; сохранение вариантов и сравнение A/B.
- **Моделирование**: положение активных спутников, видимость наземных
  пунктов и межспутниковые связи на каждом из 720 отсчётов (сутки, шаг 120 с).
- **Маршрутизация**: детерминированный поиск допустимого маршрута
  «клиент → один или несколько спутников → шлюз», пересчёт при каждом
  изменении сети; альтернативная стратегия и резервные пути.
- **Анализ**: видимость/доступность/максимальный перерыв по каждому пункту,
  причины перерывов (4 категории), критичность спутников, влияние отказа,
  быстрый подбор RAAN/фазирования, автоматическая рекомендация конфигурации.
- **Экспорт**: result JSON (маршрут для каждой пары «отсчёт × клиент»),
  effective scenario, метрики CSV, таймлайн CSV. Экспортированный сценарий
  повторно загружается сервисом.

## Быстрый запуск

Требуется Python 3.10+ (проверено на 3.12/3.14).

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Windows (PowerShell/CMD):

```cmd
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Браузер откроется на `http://localhost:8501`. API-ключи не нужны.

## Формат входных данных

JSON `cosmo-A-1.0` (см. «Описание данных»): `environment` (орбита, связь,
сетка времени), `design` (плоскости, спутники, launch_stage), `ground_sites`
(clients/gateway), `failures`, `gateway_outages`. Примеры — в `data/`.
Названия и идентификаторы объектов могут быть любыми: сервис не привязан
к C65/G_MUR/S01 и т.п. При ошибке загрузки выводится список сообщений
с путями до проблемного поля, например:

```
design.satellites[7].plane_id = "P9": плоскость 'P9' отсутствует в design.planes
```

## Алгоритм моделирования

Для каждого отсчёта `range(0, horizon_s, step_s)` (правый конец не
включается): официальный `geometry.snapshot(scenario, t)` даёт координаты,
флаги активности и рёбра; из рёбер строится граф; для каждого клиента
ищется маршрут и фиксируется статус/причина; по итогам сетки считаются
метрики. Интервалы отказов действуют как `[start_s; end_s)`. Границы
отказов, сетка и метрики соответствуют документу «Описание данных».

## Маршрутизация

- **min_hops (по умолчанию)** — BFS по графу спутников; client только
  источник, gateway только терминал; соседи обходятся по отсортированным
  ID, поэтому при нескольких допустимых маршрутах выбор детерминирован
  (минимум рёбер, затем лексикографически наименьший путь).
- **min_distance** — альтернативная стратегия: релаксация по ключу
  (суммарная длина км, число рёбер, путь). Достижимость совпадает с BFS,
  отличается конкретный путь.
- **Резервный путь** — повторный BFS с запретом внутренних спутников
  основного маршрута (node-disjoint).

## Расчёт метрик

Для каждого клиентского пункта: `visibility_fraction` (есть видимый
активный спутник), `availability_fraction` (есть полный путь до шлюза),
`max_outage_s` (самая длинная серия отсчётов без пути × step, включая
начало/конец горизонта), список перерывов с причинами
`NO_VISIBLE_CLIENT_SATELLITE` / `GATEWAY_UNAVAILABLE` / `NO_GATEWAY_CONTACT`
/ `ISL_NETWORK_DISCONNECTED`, статистика маршрутов (hops = число рёбер,
включая две наземные линии; смены маршрута; резерв).

## Работа с отказами

Отказы задаются интервалами в формах; можно применить отказ прямо из
таблицы критичности или из калькулятора «что если». Маршрут перестраивается
автоматически; при невозможности — показывается причина. Критичность
показывает, какие аппараты являются single points of failure.

## Экспорт

`schema_version = cosmo-A-result-1.0`; `effective_scenario` — полный
фактически использованный сценарий (со всеми правками); `routes` — ровно
`отсчёты × клиенты` записей `{t_s, client_id, path}`, пустой `path` —
маршрута нет; дополнительно `summary`, `metadata`, `routing_strategy`,
`generated_at`. JSON пишется в UTF-8 без NaN. Effective scenario повторно
загружается через загрузчик файла.

## Тесты

```bash
pytest -q
```

Покрытие: валидация (в т.ч. форматы сообщений), сетка времени, границы
отказов, launch_stage, маршрутизация на синтетических графах и на реальной
геометрии, метрики (включая перерывы в начале/середине/конце), экспорт
(число записей, endpoints, валидность каждого пути, повторный импорт),
parity собственного движка с официальным `geometry.py`, регрессионные
числа по всем 4 сценариям, end-to-end тесты интерфейса (AppTest).

## Основные пользовательские сценарии

1. Открыть сценарий → «Пересчитать» → карточки метрик и графики.
2. Переключить этап развёртывания 3→1 → пересчитать → сравнить.
3. Выбрать пункт и момент → маршрут в 3D-сети; прыжок к перерыву → причина.
4. Добавить отказ спутника из маршрута → пересчитать → перестроение/перерыв.
5. Сохранить вариант A, изменить RAAN/фазирование, сохранить вариант B →
   вкладка «Сравнение» → рекомендация.
6. Вкладка «Экспорт» → скачать result/scenario/CSV.

## Допущения

Коротко: детерминизм маршрутов не регламентирован кейсом — выбран
лексикографический tie-break; приоритет причин перерывов — по списку
постановки; 90% — целевой ориентир, не жёсткое ограничение. Полный список —
[docs/ASSUMPTIONS.md](docs/ASSUMPTIONS.md).

## Что сделано командой

- Инженерный сервис поверх официальной расчётной модели: UI, маршрутизация,
  метрики, диагностика, сравнение, критичность, автоподбор, экспорт.
- Собственный движок по формулам «Описания данных» и parity-тесты с

- Регрессионная сверка по четырём сценариям (см. docs/ASSUMPTIONS.md,
  раздел «Регрессионные числа»).
